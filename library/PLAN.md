# Prerender plan: open-source board library

Goal: every board in the Explore library opens instantly and looks identical to the original open-source
project: same footprints, same 3D component models, same placement, same mask/silk colours. All of the
heavy work (fetching, KiCad export, rendering, compression) runs ahead of time on the Etch Mac. The page
only loads finished static files from `deploy/etch-app/world/`.

## Pipeline

| Step | Script | Output |
| --- | --- | --- |
| 1. Find boards | `library/crawl.py` | GitHub repos with KiCad boards (topic and code search through `gh`), each pinned to a commit SHA with its SPDX licence. Unlicensed repos are dropped. One entry per `.kicad_pcb`. |
| 2. Fetch sources | `library/fetch.py` | The `.kicad_pcb`, `.kicad_pro`, `.kicad_prl` and `.kicad_sch` files, and every 3D model in the repo that the board references, at the pinned commit. |
| 3. Prerender | `library/render.py` | `board.glb` from `kicad-cli pcb export glb` (STEP models, tracks, pads, zones, silk, mask; nodes named by refdes), compressed with meshopt. Also a raytraced `thumb.webp` from `kicad-cli pcb render`, plus `parts.json` and `meta.json`. |
| 4. Index | `library/build_index.py` | `deploy/etch-app/world/index.json` and `library/manifest.json`. |

The output format is `deploy/EXPLORE_API.md` section 1.

## Identical rendering rules

1. **Exact component models.** Every footprint's `(model ...)` is resolved to the file the project
   actually uses:
   - Stock KiCad libraries: the installed KiCad 10 `3dmodels` library. Every historical variable
     (`KISYS3DMOD`, `KICAD{6..11}_3DMODEL_DIR`) points at it, so KiCad 5–9 boards resolve too.
   - Repo-local models (`${KIPRJMOD}/…`, relative paths, absolute paths, custom variables): matched in the
     repo tree by relative path first, then by file name. They are fetched at the pinned commit.
   - A STEP twin is used when a `.wrl` has one, same as KiCad's own `--subst-models`.
   - Each model's offset, scale and rotation are kept exactly as in the pcb. Hidden models stay hidden, and
     no model is ever invented for a footprint that has none.
2. **No visual shortcuts.** No mesh simplification and no dropped models to save size. Only
   meshopt compression, quantization, dedup and instancing, none of which change how the board looks.
3. **The board's own colours.** Solder mask, silkscreen and finish come from the pcb stackup or the
   project's 3D viewer settings.
4. **Recorded, not hidden.** `meta.json` records `models: {total, resolved, missing: [{ref, path}]}`.
   `identical: true` only when nothing is missing. Boards with missing models are flagged, not silently
   shipped as identical.

## Instant start in the browser

- `index.json` and thumbnails are tiny static files, so the Explore grid paints immediately.
- Hovering a card or scrolling near it prefetches its `board.glb` and `parts.json`. A service worker keeps
  visited and prefetched boards cached.
- The board page shows the prerendered `thumb.webp` in the 3D canvas at once, parses the GLB in parallel,
  then crossfades to the live 3D view. There is no spinner and no blank frame.
- three.js is served from the repo (`deploy/etch-app/vendor/three/`) with `modulepreload`, not from a CDN.

## Licences

Only allow-listed licences are imported (see `library/README.md`). Every board keeps its upstream author,
repo link, pinned commit and licence file link, and the UI shows them.

## Status

`library/manifest.json` lists every crawled board with its commit, licence, category and render status.
It is regenerated by `build_index.py`.
