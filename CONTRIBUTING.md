# Contributing to Etch

Thanks for helping. Etch is MIT licensed (see LICENSE). Bug reports, fixes, new parts and new library boards
are all welcome.

## Set up

Follow the Quickstart in README.md: `./setup.sh`, put a model key in `.env`, then `./run.sh`. On Linux or
Windows use `docker compose up --build`. `./setup.sh --check` shows what is still missing.

## The one rule for parts and boards

Every part and every board in Etch comes from a real, published open-source source, with a record of where
it came from. Nothing is drawn, modelled or generated by hand or by a model. No STEP file from a real source
means no part.

## Add a part to the parts library

The part scout already does this during a build: it pulls the symbol, footprint and STEP model from LCSC
(through easyeda2kicad) or from a KiCad footprint published on GitHub, checks it (every symbol pin has a pad,
the STEP exists) and writes it to `engine/parts/cache/<LIB>/`, with its origin in
`engine/parts/agent_index.json` under `provenance` (source URL, version, licence, model file and its SHA-256).

To contribute parts you fetched:

1. Run a build that needs the part (or ask Etch for a board that uses it) on your own backend.
2. Check the new folder in `engine/parts/cache/` and its `agent_index.json` entry. The `provenance` block must
   name a real source URL and a licence. If the licence is unclear, say so in the PR.
3. Commit only that part's folder and its index entry, then open a PR with the source link in the
   description.

For a whole KiCad library (not a single part), add it to `engine/parts/extra_libs/MANIFEST.json` with its git
URL, a pinned commit and its licence, the way the existing entries are, then run
`python3 engine/parts/fetch_extra_libs.py --rescan` and rebuild the parts library
(`uv run --frozen --project engine python -m agent.kicad_library --build`). Vendored libraries go in `vendor/<name>/` with a
PROVENANCE.md (see `vendor/espressif-kicad-libraries/PROVENANCE.md`).

## Add a board to the Explore library

Boards are crawled from GitHub, never uploaded by hand. Only repositories with a licence on the allow-list
in `library/crawl.py` are taken. To add one, put the repo and commit in `PINNED_BOARDS` in `library/crawl.py`,
run the pipeline in `library/README.md` for that board (`--only <slug>`), check it with `library/verify.py`,
and commit `deploy/etch-app/world/<slug>/` with `library/manifest.json`. Keep the author, repo, commit and
licence visible: the page shows them.

## Code changes

1. Fork, branch from `main`.
2. Keep the change focused. Match the style around it (`ruff` for Python).
3. Run the tests that cover what you touched, one file at a time, for example:

   ```bash
   PYTHONPATH=.:engine engine/.venv/bin/python -m pytest agent/tests/test_picker_repair.py -q
   ```

4. If you changed the page, open it against your own backend and try the flow you changed.
5. Open a PR that says what changed and how you tested it.

## Never commit

API keys, `.env`, `.etch.env`, build outputs (`engine/out/`), `qa/` or anything from your machine. The
`.gitignore` is a whitelist, so new top-level files need an entry there on purpose.

## Security

If you find a security problem (for example a way to make a backend run something it should not), do not
open a public issue. Contact the maintainers through GitHub first.
