How Etch turns a sentence into a board

The AI models write and repair the design. Plain code builds and checks every board, so a model never gets the last word on whether a board works.

Stage by stage

  1. Input. Text, or voice through a local Parakeet speech-to-text server. Spoken replies use OpenAI text to speech.
  2. Prefilter. Rules reject prompt injection, scripts, emoji, huge pastes and asks that are not a board, before any model runs.
  3. Router. NVIDIA's prompt task-and-complexity classifier runs on the CPU in one long-lived process. Simple asks start on the small model, harder ones on the large model.
  4. Board store. A prompt Etch has already built returns the stored board instantly.
  5. Parts screen. Etch narrows the catalog to parts that fit the ask: the full KiCad library (22,860 symbols) plus 10 open-source libraries with 1,021 extra 3D models. Wiring the full catalog into every prompt is landing now.
  6. Recipe or picker. Known device types (keyboards, soil sensors, blinkers) use a tested recipe with no model call. Everything else goes to the picker model, which returns the parts, the wiring and the checks the board should pass.
  7. Speed and reliability. If Crusoe has not answered in 12 s, the same call goes to a second Crusoe key and the first answer wins. A timeout retries once on the fast model; if that fails, the user sees which components are missing instead of a timeout.
  8. Missing parts. Parts outside the library are sourced from real published files (LCSC through easyeda2kicad, GitHub STEP models, You.com search) with provenance. Nothing is generated.
  9. Code gates. Plain code fixes pin names and reference letters, folds parallel copies, lints the wiring, and sends a synth with no sound source back to the picker.
  10. Assemble and check. KiCad places and routes the board, then ERC, DRC, schematic to board parity, ngspice and an analog solver check it, along with the benchmarks the picker wrote. A benchmark the circuit can never move is marked not checkable instead of failing forever.
  11. Repair loop. Failed checks go back to the large model as feedback, up to 4 tries.
  12. Output. Gerbers, BOM, a fab zip, a 3D model and a thumbnail. Progress streams to the dock in the studio as it happens.
  13. Edits. A change to a built board takes a known-edit shortcut when it can, and otherwise re-picks from the existing design and rebuilds.
